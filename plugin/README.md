# 锚点：ChatGPT 面板验证版

0.1.3 兼容：旧聊天缓存的本插件面板资源地址也可读取当前 HTML，避免更新后返回 Unknown resource。仅允许本插件既有哈希 URI。服务日志仅记录面板工具调用与界面资源读取，不记录用户图片、提示词或身份；可区分“工具调用成功”和“客户端请求界面”，但后者仍不能证明图片提交或生图成功。

0.1.2 修复：独立网页不再显示无法点击的“提交给 ChatGPT”；改为“在聊天中继续”，显示真实入口与手动提交退路。缺少上传能力的聊天面板有单独提示，不再误标为独立预览。新增“保存方案／导入方案”，将原始图片与设置保存为本地 `.anchor.json`，导入校验全部成功后才替换现有方案，且不会自动上传或发送。导出文件不含聊天 fileId。原生生图仍待真实宿主实测。

0.1.1 修复：本地预览改为内嵌图片数据，避免受限聊天 iframe 拦截 blob 临时地址；支持系统未给出图片 MIME 类型的 PNG/JPG/WebP；在对应上传框显示读取进度和错误，失败替换保留原图。原始图片内容不压缩、不修改。回归检查新增禁止 blob 的嵌入场景。

这是真实的 MCP 面板实现。它组织图片和要求，调用宿主的文件上传与消息接口；没有自建生图模型，也没有独立付费图片 API。ChatGPT 是否实际生图、是否能从当前面板的图片上下文中使用全部参考，必须在用户安装后的真实聊天中测试。

## 使用

安装由此 Site 发布的个人插件后，在支持面板的聊天中调用 `open_anchor_panel`（可直接说“打开锚点建筑渲染面板”）。上传一张白模，可选添加立面、光照与植物参考；确认选项，点击“提交给 ChatGPT”。上传仅在点击提交时进行。结果先留在聊天里。

`/plugin` 是同一份界面的网页准备模式，不能连接聊天、消耗套餐或生成图片。网页准备好后可保存方案，在聊天中说“打开锚点建筑渲染面板”，然后导入。只有顶部显示“已连接聊天”才可直接提交；若当前宿主未提供图片上传能力，使用“复制要求”，并在聊天输入框附上原始图片后发送。不要把网页 URL 当成已连接的插件入口。`/mcp` 是平台管理身份认证的服务入口。`anchor_status` 是无私人数据的连接自检。

## 修改设计与排版

| 文件 | 修改内容 |
| --- | --- |
| `web/panel.html` | 页面布局、区块顺序、标签 |
| `web/panel.css` | 黑白灰色板、间距、字体、圆角、响应式布局 |
| `web/workflow.js` | 锚点分类、默认约束、生成要求 |
| `web/panel.js` | 上传、状态、提交与宿主通信 |
| `server.mjs` | 工具描述、协议处理 |

`ui.ts` 将 HTML/CSS/JS 打包为单份面板，并根据内容自动更换资源标识。更新发布后，重新调用工具打开新面板；旧聊天里已经打开的实例可能仍保留旧版本。

## 运行与验证

- 项目使用 Sites Vinext 模板，原网站位于 `public/`，根路由仍保留原体验。
- `npm run dev` 启动网站及 MCP 服务；`npm test` 检查原工作流和 MCP 协议。
- `node tests/plugin-ui.smoke.mjs` 在本地预览验证上传、角色、手机布局与宿主接口模拟。
- 发布使用 Sites 官方 source/build/package 工作流，保留原 `project_id` 与私有权限。
- 接口模拟不是 ChatGPT 原生生图验收。真实验收：安装后调用状态工具、打开面板、上传用户白模、提交一次、检查聊天实际出图及几何偏差。

## 边界

不收集 API 密钥，不读取账户 Cookie，不访问用户额度。图片不传给本项目服务器；宿主上传的图片及 fileId 按聊天平台的规则处理。插件状态只用于当前面板恢复，不能代替长期项目存储。几何约束是设计指令，不能承诺像渲染器那样严格锁定。
# 验证版 0.1.4：跨设备与 Codex 入口

- 保持原个人插件身份与私有访问；同一账号、同一工作区在支持插件的 ChatGPT / Codex 客户端使用。客户端仍需实际提供原生生图能力。
- `prepare_anchor_render` 不依赖面板。接受官方文件参数，或 Codex 中实际附件的本地路径/名称；生成确定的图片顺序和约束。名称路径不是上传证明，调用者必须确认实际图片可用，再继续原生生图。
- 不读取本机文件、不下载签名 URL、不保存图片、不记录凭据。工具整理要求成功与图片生成成功分开报告。
- 网页新增“下载生图包”：原图、固定编号、生成要求、清单打成 ZIP。可以附在 Codex 聊天中；不支持 ZIP 的客户端先解压再附图。打包不自动提交。
- “保存方案 / 导入方案”支持跨设备恢复原图和设置；本地未提交的选图不会自动云同步。
- 面板仍走宿主的 `uploadFile → setWidgetState(imageIds) → follow-up`。单元测试和模拟宿主测试不等于真实客户端端到端验证。
- Codex 原生生图使用 Codex 用量；不能承诺扣除 ChatGPT 网页的独立图片额度。

验证：`node --test tests/*.test.js`；启动开发服务后运行 `node tests/plugin-ui.smoke.mjs`。用授权样例验证真实原图打包：设置 `ANCHOR_ASSETS` 指向包含 `base.png/material.png/atmosphere.png/plants.png` 的目录，再运行 `node tests/plugin-real-assets.smoke.mjs`。它不调用图片生成，生成结果需另行实测。

依据：[插件 UI](https://developers.openai.com/plugins/build/chatgpt-ui)、[文件输入接口](https://developers.openai.com/plugins/reference)、[客户端支持](https://learn.chatgpt.com/docs/plugins)、[原生生图](https://learn.chatgpt.com/docs/image-generation)。
